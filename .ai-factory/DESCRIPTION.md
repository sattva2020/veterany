# Veteran.Road — сайт ГО «Ветеран. Дорога до нового життя»

## Обзор

Многоязычный публичный сайт-визитка и кабинет для украинской ветеранской НКО «Ветеран. Дорога до нового життя». Реализован на Next.js 15 (App Router) с встроенной headless CMS Payload v3 для управления контентом, формами обратной связи, профилями ветеранов и заявками на консультации.

Цели проекта:
- Информировать ветеранов и их семьи о деятельности организации (направления помощи, новости, партнёры).
- Принимать обращения и заявки (контактные формы, бронирование консультаций, запросы на вступление).
- Вести закрытый кабинет ветерана с записями консультаций.
- Поддерживать контент на украинском (основной) и английском языках.

## Ключевые возможности

- **Лендинг** с секциями: Hero, About, Activities, How We Work, News, Testimonials, Partners, Join, Contacts (`src/components/landing/`).
- **i18n-роутинг** через Next.js middleware (`/uk/...`, `/en/...`) с автодетектом по cookie `NEXT_LOCALE` и `Accept-Language`.
- **Payload CMS** — раздельные группы маршрутов `(frontend)` и `(payload)`; админка на украинском, контент локализован (`localization` в `payload.config.ts`).
- **Коллекции CMS:** `Activities`, `News`, `Partners`, `JoinOptions`, `ContactSubmissions`, `VeteranProfiles`, `Consultations`, `Media`, `Users`. Глобальный объект `SiteSettings` хранит шаги, отзывы и статистику для лендинга.
- **Кабинет ветерана** (`/cabinet`) — логин, профиль, история консультаций.
- **Бронирование** консультаций (`/booking`).
- **CRM-вебхук** (`api/crm-webhook`) для входящих интеграций.
- **SEO/AI-search:** `robots.ts`, `sitemap.ts`, `JsonLd.tsx`, `public/llms.txt`, локализованные метаданные.
- **UI-фичи:** анимированные счётчики, ScrollReveal, плавающий ChatWidget, модальное окно помощи.

## Стек технологий

- **Язык:** TypeScript 5.7 (`type: module`, ESM).
- **Фреймворк:** Next.js 15.4 с App Router (`--webpack` режим dev), React 19.
- **CMS:** Payload CMS v3.82 (`@payloadcms/next`, `@payloadcms/ui`, `@payloadcms/richtext-lexical`).
- **База данных:** SQLite через `@payloadcms/db-sqlite` (файл `database.db` в корне; `DATABASE_URI` env).
- **Локализация:** Payload `localization` (uk/en) + Next.js middleware на `[locale]`.
- **Стили:** Sass + единый `src/styles/globals.css` (~62 KB), `payload-base.css` и `payload-components.css` для админки.
- **Изображения:** Sharp 0.34.
- **GraphQL:** `graphql` 16 (для Payload).
- **Утилиты:** `cross-env`.
- **Контейнеризация:** `Dockerfile` и `.dockerignore` присутствуют.

## Архитектура

Подробные архитектурные правила и границы модулей описаны в `.ai-factory/ARCHITECTURE.md`.
Паттерн: **Modular Monolith**.

## Архитектурные заметки

- **Группировка маршрутов** Next.js: `(frontend)` для публичного сайта и кабинета, `(payload)` для админки и Payload API. Это позволяет иметь разные layout и не пересекаться по стилям.
- **Локали** обрабатываются двумя слоями: middleware редиректит `/<path>` → `/<locale>/<path>`; Payload параллельно локализует контент в БД.
- **Получение данных** для лендинга — серверный компонент `app/(frontend)/[locale]/page.tsx` дергает `getDictionary` (статические JSON-словари) и `getLandingData` (Payload local API через `payload-client`).
- **Динамический рендеринг** главной страницы (`export const dynamic = 'force-dynamic'`) — данные актуальны на каждый запрос.
- **Типы Payload** генерируются в `src/payload-types.ts` командой `npm run generate:types`.
- **MCP `postgres`** настроен в `.mcp.json`, но фактически проект использует SQLite — MCP сейчас не применим к рабочей БД. Переключение на Postgres потребовало бы смены адаптера и миграций.

## Нефункциональные требования

- **Локализация:** uk — основная, en — вторичная. Любой публичный контент должен быть готов к переводу (словарь `src/dictionaries/{uk,en}.json` + локализованные поля Payload).
- **SEO:** метаданные на каждой локали, `robots.ts`, `sitemap.ts`, JSON-LD, `llms.txt` для AI-краулеров.
- **Безопасность:** секреты через переменные окружения (`PAYLOAD_SECRET`, `DATABASE_URI`, `GITHUB_TOKEN`); ни один секрет не должен попадать в репозиторий или артефакты.
- **Производительность:** изображения через `sharp`, статические словари кэшируются, серверные компоненты для лендинга.
- **Совместимость:** Node.js 20+ (предполагается из стека Next 15 / React 19), запуск под Windows-окружением разработчика.
- **Доступность:** контент должен оставаться читаемым без JS (серверный рендеринг секций), интерактивные виджеты — дополнение, а не основа.

## Известные особенности и ограничения

- В корне присутствует `database.db` (SQLite) с реальными данными — обращаться осторожно, не коммитить случайно.
- В корне лежит `.env` (не должен попадать в git; убедитесь, что он в `.gitignore`).
- Файлы дизайн-референсов и эмблем хранятся в `docs/dev/desing/` (опечатка в имени папки сохранена).
- Скрипты `lint` и `test` отсутствуют в `package.json` — при добавлении проверок их нужно завести.
