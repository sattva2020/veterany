# Комплексное исправление блокеров аудита перед передачей клиенту

**Date:** 2026-06-10 17:40
**Files:** src/collections/{ContactSubmissions,Consultations,VeteranProfiles,Users}.ts, src/payload.config.ts, CLAUDE.md, scripts/{reseed-prod,seed-hero-stories}.mjs, src/middleware.ts, src/app/(frontend)/{cabinet,booking,privacy}/layout.tsx, src/app/sitemap.ts, src/app/(frontend)/[locale]/page.tsx, src/components/{Header,Footer,ChatWidget,HelpModal}.tsx, src/components/landing/{HeroSection,TestimonialsSection}.tsx, Dockerfile, docker-compose.yml, .env.example, README.md, docs/*.md, AGENTS.md
**Severity:** critical

## Problem

Аудит перед передачей клиенту выявил четыре класса дефектов:
1. Анонимное чтение PII через Payload REST (`access.read: () => true` в ContactSubmissions, Consultations, VeteranProfiles); коллекция Users без access-правил — редактор мог назначить себе role=admin; fallback-секрет `default-secret-change-me`; пароль админа прода в CLAUDE.md и сид-скриптах.
2. Разделы /cabinet, /booking, /privacy недостижимы: middleware префиксовал локаль → 404; их layouts не рендерили html/body; sitemap публиковал битые `/uk/privacy`.
3. Фейковый функционал: ChatWidget терял сообщения и показывал несуществующий телефон +38 (044) 123-45-67 (также в HelpModal); аудиоплеер отзывов — имитация без `<audio>`; drop-cap в fallback-историях Hero собирался из тел с уже отрезанной первой буквой («ьогодні…»).
4. Деплой невоспроизводим: нет docker-compose.yml и .env.example, контейнер от root без HEALTHCHECK; документация описывала SQLite при фактическом Postgres.

## Root Cause

- Access-правила открывались «чтобы заработало» на этапе прототипа и не пересматривались: формы должны были писать анонимно (create), но read скопирован тем же `() => true`.
- Разделы кабинета создавались до ввода i18n-middleware; middleware добавили позже с матчером «всё без локали», не проверив существующие маршруты вне [locale].
- UI-макет (Variant C из дизайн-системы) перенесён буквально, включая декоративный аудиоплеер и телефон-заглушку из мокапа; fallback-данные Hero скопированы из макета, где первая буква выносилась в отдельный span.
- Документация писалась до миграции SQLite→Postgres (коммиты 256a936…5ad06b0) и не была синхронизирована.

## Solution

- Payload access: read PII — только `req.user.collection === 'users'`; Consultations — ветеран видит свои через query-constraint `{ veteran: { equals: req.user.id } }`; VeteranProfiles — self или команда; Users — isAdminOrSelf + field-level access на `role` (только админ). Fail-fast в payload.config.ts: throw в production без PAYLOAD_SECRET/DATABASE_URI. Креды удалены из CLAUDE.md; скрипты требуют SEED_* env без fallback.
- Роутинг: /cabinet, /booking, /privacy добавлены в SKIP_PATHS и matcher middleware (разделы осознанно нелокализованы); каждому дан layout с `<html lang="uk">`+fonts+globals.css (зеркало [locale]/layout); sitemap публикует их без префикса локали; ссылки (Header cabinetLink, Footer privacy) исправлены.
- Честный UI: телефон приходит из SiteSettings.phones через проп (Header→HelpModal, page→ChatWidget) и не показывается, если не заполнен; ChatWidget шлёт сообщение в /api/crm-webhook (best-effort) и отвечает направлением на форму «Потребую допомоги»; аудиоплеер отзывов удалён; первые буквы fallback-историй восстановлены (drop-cap = charAt(0) от полного слова); бургер-меню стало `<button>` c aria-expanded, body.overflow чистится в useEffect cleanup; стрелки карусели игнорируются при фокусе в INPUT/TEXTAREA.
- Деплой: Dockerfile — USER node + chown + HEALTHCHECK (wget /uk); добавлены docker-compose.yml (postgres 16 + web, required-переменные через `${VAR:?}`) и .env.example; вся документация переведена с SQLite на Postgres.

## Prevention

- Для каждой новой коллекции Payload сразу писать полный блок access (read/create/update/delete) и спрашивать: «могут ли это читать анонимы?» — особенно для форм с PII. Паттерн: `create: () => true` для публичных форм НЕ означает `read: () => true`.
- При добавлении middleware с rewrite/redirect — прогнать все существующие top-level маршруты `src/app` через матчер.
- Декоративные элементы из дизайн-макетов (плееры, телефоны, счётчики) проверять на «есть ли за этим реальные данные» перед переносом в продакшен-код.
- После смены инфраструктуры (БД, хостинг) — grep по docs/ и CLAUDE.md/AGENTS.md на упоминания старого стека.
